# Базовый аппаратный замер

Замер: 2026-11-13 00:39:37 EET. Исходная ревизия приложения: `031311e43df78fc582a82dfac6cf4f8ec09ec8d0`; добавлены только режим запуска с окном и поле `environment.headless` в runner. Сцена и маршруты не изменены.

## Условия

- ПК пользователя, NVIDIA GeForce RTX 3050 Laptop GPU, 4096 MiB; драйвер NVIDIA 610.74 по `nvidia-smi`.
- WSL2 / WSLg, ядро `6.6.87.2-microsoft-standard-WSL2`, графическая сессия X11, Mesa 25.2.8. Это аппаратный рендер через WSL, не нативный Chrome Windows.
- Google Chrome for Testing 145.0.7632.6, окно браузера (`headless: false`), временный профиль, production-сборка.
- Canvas 1280×720, devicePixelRatio 1. Это размер области рендера, не разрешение монитора.
- Подтверждённый WebGL renderer: `ANGLE (Microsoft Corporation, D3D12 (NVIDIA GeForce RTX 3050 Laptop GPU), OpenGL 4.6)`.
- Включены все текущие модули: `simulation`, `lighting`, `ground`, `beacon`. Сценарии: круговой обзор площадки и облёт маяка; измеряется вся сцена вместе с UI.
- По 1 секунде прогрева и 10 секунд замера на сценарий. Базовый повтор выполнен после завершения проверок и сборки; остальные приложения и питание ноутбука не контролировались.

## Повторение

```sh
GALLIUM_DRIVER=d3d12 MESA_D3D12_DEFAULT_ADAPTER_NAME=NVIDIA MODULE_TEST_SECONDS=10 npm run test:fps -- --headed
```

Запускать с доступом к графической сессии и GPU этого ПК. В текущем sandbox GPU недоступна, поэтому замер выполнен вне sandbox. Переменные выбирают установленный WSL-драйвер только для процесса. Без них диагностический Chromium выбрал программный llvmpipe, WebGL не создался. Не включать такой результат в аппаратную базовую линию.

Перед сравнением проверить renderer, версию браузера, размеры canvas, включённые модули и маршруты. Сохранить одинаковые питание и графическую сессию, завершить параллельные сборки и тяжёлые задачи. Запуск открывает отдельное окно и не использует личный профиль браузера.

## Ограничения

Это базовая линия лёгкой демонстрационной сцены, не бюджет готового города. Значения около 60 FPS согласуются с ограничением вывода кадров; частота экрана/VSync отдельно не измерялись, запас GPU этим замером не определён. Ограничения частоты кадров не отключались.

Текущая политика `fps.config.json` пропускает средний FPS от 30. Полученный PASS не подтверждает строгий порог 60 FPS; целевой бюджет ещё предстоит согласовать. Память, время GPU и загрузка городских ресурсов в этой базовой линии не измерены. Изменение геометрии, текстур, теней и маршрутов требует нового замера, старую лёгкую сцену нельзя выдавать за представительный городской тест.
