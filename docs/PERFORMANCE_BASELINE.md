## Повторение

```sh
GALLIUM_DRIVER=d3d12 MESA_D3D12_DEFAULT_ADAPTER_NAME=NVIDIA MODULE_TEST_SECONDS=10 npm run test:fps -- --headed
```

Запускать с доступом к графической сессии и GPU этого ПК. В текущем sandbox GPU недоступна, поэтому замер выполнен вне sandbox. Переменные выбирают установленный WSL-драйвер только для процесса. Без них диагностический Chromium выбрал программный llvmpipe, WebGL не создался. Не включать такой результат в аппаратную базовую линию.

Перед сравнением проверить renderer, версию браузера, размеры canvas, включённые модули и маршруты. Сохранить одинаковые питание и графическую сессию, завершить параллельные сборки и тяжёлые задачи. Запуск открывает отдельное окно и не использует личный профиль браузера.

## Пакеты дорожных поверхностей

В object-rendering добавлен явный пакетный путь для static с одной прямоугольной деталью на LOD и заданным opaque-материалом. World использует его для road/sidewalk/curb. Группировка по ячейке 128, идентичности материала и LOD; индивидуальные дистанции сохранены. До 155 экземпляров поверхностей и до 20 пакетов на обычном контрольном маршруте (максимумы до frustum culling, не фактические draw calls).

Исправлены две ошибки реализации: thin-instance атрибуты хранятся на Geometry, поэтому каждый пакет обязан вызвать makeGeometryUnique до записи буферов; при переиспользовании буфера сначала задаётся новое thinInstanceCount, затем вызывается thinInstanceBufferUpdated, иначе загрузка ограничена старым числом экземпляров. Добавлены регрессионные проверки изоляции Geometry/атрибутов, удаления соседнего пакета и изменения состава 2→1→2. Буферы переиспользуются и растут по необходимости, общая AABB пересчитывается только при изменении состава/матриц. Аппаратный снимок после исправлений показывает дороги и тротуары на прежних местах. Замеры промежуточных вариантов со сломанным изображением не считать результатом оптимизации.

Финальный обычный прогон `2026-11-13T02:14:46.670Z`: world **58.64 FPS**, P95 **20.5 мс**, те же RTX 3050 / WSL D3D12, Chromium 145 с окном, 1280×720, весь реестр и прежний маршрут. Обычный отчёт сохранён как artifacts/fps-report.json.

Source vertices, triangles and fitted window UVs are copied verbatim. Height-based visibility thresholds, close detail sections, shadow settings and collision data retain their existing values. Culling at the edge of a square is coarser because the batch shares one bounding box.

Matched production builds ran sequentially on an RTX 3050 Laptop GPU via ANGLE/D3D12, uncapped at 1280×720. The full demo had 8 NPCs, vehicles, atmosphere and night lighting enabled. Each fixed view had two 3 s samples after warm-up. FPS, per-sample P95 frame time and draw calls are averaged across the two samples.

### Batched foliage

Added 542 mapped placements, including 366 park trees, 172 street trees and four plaza planters. Each 64 m square uses one cutout mesh with textured bark and foliage. The shader uses one shared 512×256 atlas with alpha testing. Trees receive shadows and are excluded from the shadow caster list. Sections load at 160 m and unload at 210 m.

Sequential production runs on the RTX 3050 Laptop at 1280×720, with the full demo and two 3 s samples per view, gave 55.5 → 58.1 FPS at Daley Plaza, 69.2 → 72.1 in a park and 59.4 → 65.2 above the city. The samples showed no regression. Higher FPS in the tree build falls within run-to-run variation and does not establish a speedup. The three views had 9, 21 and 2 enabled tree batches respectively, before frustum culling. Peak cgroup memory was about 982 MB in both runs without OOM or browser errors. Plaza and park screenshots confirmed transparent space between leaves after enabling diffuse alpha in the material. This was a short, fixed-camera comparison.

Tree LOD adds a second representation to each 64 m batch. From 32 to 60 m, complementary dither coverage switches from 54 triangles per tree to 14, while keeping one visible mesh outside the overlap. The near mesh and far mesh are created individually on demand. The new alpha-cutout crown shares the same 512×256 atlas. In the hardware park sweep, one nine-tree batch went from 486 to 126 triangles, and the GPU run recorded complementary fade bounds with no browser errors. A single 2.5 s moving-camera sample ran at 64.8 FPS with a P95 of 33.5 ms. No same-route comparison to the original tree representation was made.

### Sprint, flight and river swim

Production browser route with the existing car, atmosphere, night-lighting module and eight NPCs enabled. Real key events move the player from a walk through a jog and sprint, climb above the skyline, cross to the river at boosted flight speed, hover, descend, fall into the water, swim, dive and resurface. RTX 3050 Laptop via ANGLE/D3D12 at 1280×720, 1401 frames over 22.6 s, 61.9 FPS average, P95 28.1 ms. Cgroup peak 1.00 GB with the 2 GiB cap and swap disabled. No browser errors or OOM. This route does not isolate a performance change versus the previous build.

The avatar still uses one skinned primitive, the same 65 joints and shared textures. The exported GLB went from 1,394,688 to 1,258,860 bytes after resampling and deduplicating the expanded clip set. Runtime blends only currently playing groups and keeps the existing distance and frustum animation culling. The collision system reuses the static spatial index, precomputes terrain triangle denominators and skips blocked or idle axes during the high-speed sweep.
