# Симуляция (`simulation`)

Опциональный клиентский адаптер headless-часов из `src/simulation/authority.ts`, включён в стартовый набор. Зависимостей нет. Core передаёт монотонную разницу времени через `onFrame`; модуль вызывает `authority.advance` до рендера. Игровой режим не нужен.

Часы теперь вызывают зарегистрированные headless-системы на каждом фиксированном тике, включая догоняние после перерыва. Порядок — порядок регистрации; регистрация не заменяет headless-правила клиентским callback из ввода. Новая система подключается/удаляется через registerSystem(step, ownerScope), при остановке потребителя снимается. Клиентский потребитель — characters. В текущем графе сначала выполняется система characters, затем временные тестовые системы по регистрации. Это локальная сборка authority, не передача функции по сети. Сервер позже запускает те же headless-функции без клиентского setup.

Публичное определение — `simulationModule` из `index.tsx`. API часов: `snapshot(): Snapshot` — сериализуемый снимок часов. Потребители снимка часов — `beacon` и `characters`. Зависимость от модуля автоматически включает симуляцию. Изменение API согласовывать с потребителями.

React-компонент `SimulationInfo` подписывается на кадры через `useEffect` с очисткой подписки. Инфо-панель через `core.panels` использует готовый `DataList` из Radix Themes и показывает секунды, tick и pendingTicks. Закрытие панели не останавливает часы. При пересоздании сцены создаётся новая authority с нуля. Правила фиксированного шага и задолженности остаются в headless-логике; DOM и Babylon туда не переносить.

Категория в списке модулей: «Системы».

Клиентский сценарий `test` не задан.

Локальный адаптер создаёт одну `session` из `src/simulation/session.ts` на сцену. Characters и vehicles открывают в ней каналы по стабильным ID. Команды проходят через очередь своего канала к валидаторам authority, а канал публикует последний снимок после шага и сброса. `worldSnapshot()` возвращает часы и текущие снимки подключённых сущностей, включая двери персонажа и автомобиля. Вызывать между шагами. Закрытие канала снимает его снимок и разрешает ожидающие запросы. Снимки и очереди живут в памяти сцены. При замене адаптера входом клиента остаётся отправка команды, чтением — кэш полученных снимков. Сохранение мира потребует отдельной схемы, поскольку публичный снимок не содержит внутреннее состояние симуляции.
