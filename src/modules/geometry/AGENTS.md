# Геометрия (`geometry`)

Клиентский визуальный модуль категории «Рендеринг», зависимостей нет. Зарегистрирован в `src/registry.ts`, вне стартового набора. Сам по себе не размещает демонстрационные объекты: потребитель создаёт модели через API, сценарий временно создаёт тестовую группу.

Публичное определение — `geometryModule` из `index.ts`. Экспортируемые типы — `GeometryPart`, `GeometryModel`. API экземпляра: `createModel(name, parts, ownerScope): GeometryModel`. Возвращает Babylon `TransformNode` и `ReadonlyMap` именованных поверхностей с массивами `Mesh`. Это только клиентское представление, не JSON-протокол или состояние authority. Публичных потребителей пока нет; будущий `materials` зависит от этого модуля и назначает оформление через поверхности.

Каждая деталь пока прямоугольная: обязательные непустое `surface` и `size: [x,y,z]`, необязательные локальные `position` и `rotation` (радианы). Размеры положительные конечные, преобразования конечные; проверяются до создания ресурсов. Повтор имени поверхности группирует несколько деталей. Имена моделей — отладочные, не authority ID. Корень позволяет перемещать составную модель целиком. Каталог шаблонов, другие формы, LOD и игровые коллизии пока отсутствуют.

Все детали делят геометрию единичного куба; меши имеют независимые преобразования и допускают раздельное назначение материалов. Клоны не сокращают число draw calls; группировка совместимых вариантов относится к будущему `object-rendering`. Не заменять их инстансами без проверки возможности раздельных материалов. Запасной одноцветный материал не требует света; он останется после отключения будущего оформления.

Материал и исходный скрытый меш сразу регистрируются в scope модуля. Модель сразу регистрируется в переданном scope владельца; ранний `root.dispose()` разрешён и не уничтожает общую геометрию/материал. Реестр живых корней удаляет записи при dispose, остановка модуля очищает оставшиеся модели перед общими ресурсами. Ошибка сборки удаляет частичную модель. После остановки API отклоняет создание.

Будущий `materials` не должен уничтожать запасной материал; при остановке сначала восстанавливает запасное оформление своих поверхностей и затем освобождает собственные ресурсы. Доступ к запасному оформлению и уведомления о новых моделях согласовать в задаче этого модуля; глобальный обход сцены не использовать.

Сценарий `test`: 4 секунды обзора 25 составных моделей (по 2 детали), плюс 1 секунда прогрева runner. Использует только отдельный scope теста, создаёт модели вокруг начала координат; камера и управление восстанавливаются существующим runner. Тестовые модели удаляются при завершении/отмене/ошибке. В сцене могут оставаться объекты других включённых модулей.

Проверки: `tests/geometry.test.ts` через Babylon NullEngine проверяет разделение буферов, поверхности, независимость моделей, валидацию и очистку при остановке/ошибке. Браузер: включить модуль, запустить сценарий, остановить досрочно и повторить; без света группа остаётся видимой, вне сценария временных моделей нет. Аппаратный FPS сравнивать только при одинаковом наборе модулей и маршрутах; новая тестовая сцена отличается от исходной базовой линии.
