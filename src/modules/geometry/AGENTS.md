# Геометрия (`geometry`)

Клиентский визуальный модуль категории «Рендеринг», зависимостей нет. Зарегистрирован в `src/registry.ts`, вне стартового набора. Предоставляет функциональный API; объекты размещают потребители.

Публичное определение — `geometryModule` из `index.ts`. Экспортируемые типы — `GeometryPart`, `GeometryModel`, `FaceUV`. API экземпляра: `createModel(name, parts, ownerScope, detail = 0): GeometryModel`. Возвращает Babylon `TransformNode` и `ReadonlyMap` именованных поверхностей с массивами `Mesh`. `validateParts(parts): void` проверяет описание без создания ресурсов; `createModel` использует ту же проверку. Потребитель обоих методов — `object-templates`, который проверяет все LOD до создания выбранного уровня. `object-rendering` напрямую использует `createModel` для ленивого создания уровней из уже проверенного описания. Это только клиентское представление, не JSON-протокол или состояние authority. `materials` зависит от этого модуля и подключает оформление по именам поверхностей.

Каждая деталь пока прямоугольная: обязательные непустое `surface` и `size: [x,y,z]`, необязательные локальные `position` и `rotation` (радианы), faceUV — шесть UV-прямоугольников [u0,v0,u1,v1] в порядке Babylon +Z/-Z/+X/-X/+Y/-Y. Координаты UV конечные в 0…1, u0<u1 и v0<v1. Размеры положительные конечные, преобразования конечные; проверяются до создания ресурсов. Повтор имени поверхности группирует несколько деталей. Имена моделей — отладочные, не authority ID. Корень позволяет перемещать составную модель целиком. Каталог шаблонов вынесен в `object-templates`; автоматический выбор LOD находится в `object-rendering`, другие формы и игровые коллизии пока отсутствуют.

Все детали делят геометрию единичного куба; меши имеют независимые преобразования и допускают раздельное назначение материалов. Клоны не сокращают число draw calls; object-rendering уже использует отдельные единичные модели для thin-instance пакетов совместимых статичных поверхностей. Обычный createModel сохраняет отдельные меши. Не заменять их инстансами без проверки возможности раздельных материалов. Запасной одноцветный материал не требует света; он останется после отключения будущего оформления.

Материал и исходный скрытый меш сразу регистрируются в scope модуля. Модель сразу регистрируется в переданном scope владельца; ранний `root.dispose()` разрешён и не уничтожает общую геометрию/материал. Реестр живых корней удаляет записи при dispose, остановка модуля очищает оставшиеся модели перед общими ресурсами. Ошибка сборки удаляет частичную модель. После остановки API отклоняет создание.

getSurfaceMaterial(surface, detail=0) возвращает материал текущего оформления либо fallback. detail — неотрицательный safe integer; индекс за пределами массива использует последний материал. registerSurfaceMaterials(ReadonlyMap<string, readonly Material[]>, ownerScope) подключает единственный активный набор; имена непустые, уровни непустые, все материалы текущей сцены. Таблица и массивы копируются. Подключение/отключение обновляет существующие модели из собственного реестра, новые создаются сразу оформленными. Только назначения, совпадающие с прежним автоматическим материалом, заменяются: явные сторонние назначения сохраняются. При очистке снимается только своё подключение и восстанавливается fallback до уничтожения материалов владельцем. Провайдер не уничтожает fallback. Geometry не владеет подключёнными материалами и не импортирует materials; глобальный обход сцены не нужен. Потребители API: materials, object-rendering; detail передают object-templates/object-rendering при создании выбранного LOD.

Клиентский сценарий `test` отсутствует: модуль не поставляет контент и не создаёт демонстрационные объекты для FPS-замеров. Обзоры существующего контента принадлежат соответствующим контентным модулям.

Проверки: `tests/geometry.test.ts` через Babylon NullEngine проверяет разделение буферов, поверхности, независимость моделей, валидацию и очистку при остановке/ошибке. При включении модуля новых видимых объектов и кнопки ▶ нет. Проверку отображения выполнять в сценариях реальных потребителей.


UV-раскладки используют штатный MeshBuilder.CreateBox({faceUV}). Каждый уникальный набор шести прямоугольников получает один скрытый единичный source и собственную Geometry; все модели с той же раскладкой делят её. Обычный куб сохраняет исходные UV, новые раскладки его не меняют. Источники сразу связаны со scope модуля, живут до остановки; это маленький кеш доверенных рецептов, не отдельная модель мира. При множестве динамически уникальных раскладок пересмотреть бюджет кеша. Модель с атласом остаётся одним мешем/материалом, submeshes по граням не добавляются. Проверки дополнены изоляцией UV-геометрии, совместным использованием, диапазонами и очисткой.

У атласных боксов (faceUV) вертикальная координата V нормализована на всех четырёх стенах по локальной Y: верх использует v0, низ v1. Стандартный Babylon задаёт разный вертикальный порядок на противоположных гранях; без нормализации отметка высоты h отражалась в 1-h на части стен. Верхняя/нижняя грани и обычный куб без faceUV не изменены. Исправление выполняется один раз при создании общего UV-source, не на экземплярах/кадрах. Регрессионный тест проецирует границы и центр отметки на все четыре стены.
