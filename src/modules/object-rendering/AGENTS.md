# Отрисовка объектов (`object-rendering`)

Функциональный клиентский модуль категории «Рендеринг». Публичное определение — `objectRenderingModule` из `index.ts`, зависимости — `geometryModule` и `objectTemplatesModule`. Зарегистрирован вне стартового набора; включение автоматически включает зависимости. Сам не регистрирует шаблоны, не размещает контент, не имеет панели и сценария ▶.

## API

- `createObject(templateId, name, parameters, ownerScope, mobility = 'dynamic', batchMaterial?)` разрешает шаблон один раз и возвращает `{root, level(), onModelCreated, refreshTransform()}`. `root` — Babylon `TransformNode` экземпляра, допускает положение, поворот, масштаб и родителя. `level()` — выбранный индекс LOD или `null` при скрытии/до первого кадра/после удаления. `onModelCreated` — Babylon Observable с `GeometryModel`, уведомляет один раз при создании каждого посещённого LOD перед его включением; подписку связать со scope. Нужен для назначения оформления без обхода сцены, потребитель — `world`. При ошибке подписчика экземпляр удаляется; Observable очищается при dispose. `name` — отладочное имя, не authority ID. Пустое имя, неизвестный шаблон, некорректные параметры и не представимые конечными границами размеры отклоняются до создания корня.
- `refreshTransform()` ставит экземпляр в очередь пересчёта и переиндексации на ближайшем кадре. Для `mobility: 'static'` вызывать после изменения положения, поворота, масштаба, pivot или родителя/его преобразования. Начальные изменения между createObject и первым кадром входят в первую индексацию автоматически. По умолчанию режим `dynamic`: изменения отслеживаются автоматически, включая уже пересчитанную снаружи матрицу. После удаления экземпляра вызов отклоняется.
- `getStats()` возвращает `{objects, cells, candidates, boundsUpdates, dynamic, batches, batchedInstances}`: объекты/ячейки индекса, кандидаты последнего кадра, число пересчитанных границ и число динамических объектов. `batches` — текущие пакеты поверхностей, `batchedInstances` — включённые в них экземпляры до frustum culling. Это не фактические draw calls.
- `getDistanceOrigin(): DistancePoint | null` возвращает копию мировой точки отсчёта. По умолчанию это текущая активная камера; её view matrix обновляется перед чтением глобальной позиции. Если камеры нет — `null`.
- `setDistanceSource(read, ownerScope)` подключает единственный явный источник `() => DistancePoint | null`. Повторное подключение при активном источнике отклоняется. Scope снимает только своё подключение, после чего снова используется камера. Публичный тип `DistancePoint` — `{x,y,z}` с конечными числами.

В игре потребитель подключает отображаемую позицию управляемого героя, возвращая `null`, пока герой отсутствует. При `null` объекты скрыты, камера не подставляется. Неконечные координаты — явная ошибка. Модуль не импортирует управление игроком или игровой режим; отдельного `view-distance` нет. Публичный потребитель создания объектов — `world`, который явно использует режим static для неподвижного города.

## Выбор представления

Одна подписка на `scene.onBeforeRenderObservable` выполняет отбор и обновление перед отрисовкой; свой цикл/таймер не создаётся. В кадре точка отсчёта читается один раз. Вызов `createObject` не создаёт LOD-меши сразу: потребитель успевает задать преобразование до первого кадра.

Общая локальная AABB охватывает геометрию всех уровней шаблона, включая размеры, позиции и повороты деталей. Она вычисляется без создания мешей из прямоугольных деталей текущего `geometry`. Мировая AABB вычисляется при первой индексации и после изменения преобразования. Статичные объекты не обходятся для проверки матриц; динамические используют штатную синхронизацию Babylon и updateFlag кешированной матрицы, перестраивая границы и индекс только при изменении. Расстояние — евклидово до ближайшей точки мировой AABB, внутри неё — ноль. Поэтому смена уровня не меняет границу отсчёта, крупный объект не скрывается по расстоянию до центра. Мировая AABB может консервативно охватывать лишнее пространство при повороте составного объекта.

`spatial-grid.ts` — приватная сетка X/Z с ячейкой 128, не отдельный модуль. Объект записывается в ячейки своей мировой AABB, расширенной на индивидуальный hideDistance; поэтому один запрос по ячейке точки отсчёта даёт консервативный набор кандидатов. Только им считается точное 3D-расстояние и LOD. При выходе из набора ранее включённый объект выключается один раз; уже скрытые дальние объекты не перебираются. При отсутствующей точке выключаются активные объекты, первичная индексация откладывается до её появления.

Чтобы крупная земля/объект с огромной дальностью не раздували индекс, влияние более 256 ячеек либо небезопасные целочисленные координаты отправляются в отдельный список, проверяемый всегда. Это консервативный fallback, не раннее скрытие. Пересматривать при значительном числе таких объектов. Отрицательные координаты обрабатываются через Math.floor; размеры и разные дальности учитываются до выбора кандидатов.

При `distance >= hideDistance` объект скрыт; на точном пороге уровня выбирается следующий. Ровно один целый составной LOD включён, остальные отключены. Кеш посещённых уровней создаётся лениво через `deps.geometry.createModel` с индексом LOD в detail оформления; при повторном выборе уровень используется снова. Скрытие не выгружает ресурсы. Кеш живёт до удаления экземпляра; eviction добавлять по замерам. Гистерезис и плавные переходы пока отсутствуют.

Картинка не меняет authority, коллизии, AI или события. Потребитель изменяет преобразование только корня, не геометрию внутренних уровней; иначе вычисленные по описанию границы перестанут соответствовать изображению. Перерегистрация ID шаблона не заменяет снимок существующего экземпляра: для обновления пересоздать его явно.

## Очистка и проверки

Корень немедленно регистрируется в scope потребителя. Корни созданных уровней связаны с его dispose; ранний `root.dispose()` удаляет экземпляр из списка обновлений, уничтожает все посещённые уровни, но не общую геометрию соседних объектов. Остановка модуля снимает подписку, очищает оставшиеся объекты и источник. Вызовы API после остановки отклоняются.

`tests/object-rendering.test.ts` использует только Node/NullEngine-фикстуры: точные границы нескольких уровней и исчезновения, повторное использование уровней, составные границы с поворотами/масштабом/родителем, мировую камеру и явный источник, отсутствие героя/камеры, ошибки координат и размеров, очистку. Дополнительно проверяются кеш статичных границ и refreshTransform, переходы между ячейками, смена родителей и повторно используемые векторы, разные дальности, края крупных объектов и fallback, совпадение с прямым расчётом на положительных/отрицательных границах ячеек и удаление из callback. Никакого контента для FPS-замеров не добавлять. Браузерную проверку и производительность выполнять с контентным world; его diagnostics записывает кандидатов LOD и пересчёты границ. Ресурсы посещённых LOD пока не выгружаются из Babylon, это не world-streaming.


## Пакетные поверхности

Необязательный `batchMaterial: Material | string` в createObject включает thin instances вместо отдельных LOD-моделей. Требует static, одну прямоугольную деталь без индивидуальной faceUV в каждом LOD и материал текущей сцены без alpha blending. Параметры, скрытие и level() прежние; `onModelCreated` на этом пути не вызывается, оформление явно задано материалом. Прямой Material остаётся собственностью потребителя, его замена требует пересоздания объекта. Строка означает имя поверхности: материал читается через deps.geometry.getSurfaceMaterial(surface, выбранный LOD); смена провайдера автоматически перестраивает только затронутые группы на ближайшем кадре, включая возврат к fallback. Пустое строковое имя отклоняется. Обычный путь без batchMaterial сохраняет прежний контракт.

Приватный surface-batches.ts объединяет выбранные представления по ячейке 128×128 позиции корня, идентичности материала и индексу LOD. Разные размеры прямоугольников совместимы: матрица детали умножается на мировую матрицу корня; исходная форма — единичный куб через geometry; каждый пакет вызывает makeGeometryUnique до создания thin-instance буферов. Эти атрибуты Babylon хранит на Geometry: совместное использование Geometry между пакетами перетирает матрицы и ломает отрисовку. Произвольные формы этим правилом объединять нельзя. Вырожденные и зеркальные мировые преобразования на пакетном пути отклоняются: смешанный знак determinant нарушает отсечение граней instanced draw. Положительный масштаб, поворот, parent и refreshTransform поддержаны. Отключение корня/предка скрывает экземпляр при следующем обновлении LOD.

Индекс и индивидуальные расстояния применяются до помещения в пакет. На смене уровня, скрытии, refreshTransform или удалении меняется только затронутая группа. Изменившиеся пакеты обновляются один раз перед кадром: GPU-буфер переиспользуется через thinInstanceBufferUpdated, thinInstanceSetBuffer вызывается только при росте ёмкости. thinInstanceCount ограничивает активную часть буфера; общая AABB явно пересчитывается через thinInstanceRefreshBoundingInfo. Не учитывать запас ёмкости как реальные экземпляры. Пустой пакет сразу удаляется, исходный единичный куб не показывается. Границы пакета охватывают все его матрицы, включая длинные сегменты за пределами ячейки. Не обещать индивидуальный frustum culling внутри одного draw. Меши пакетов зарегистрированы в scope модуля через geometry; экземпляры удаляют свои записи при dispose.

Node-проверки дополнительно покрывают объединение разных размеров/позиций, корректные матрицы и границы, перенос между ячейками, LOD, скрытие, разные материалы, изоляцию Geometry и GPU-атрибутов между пакетами и обычными моделями, отключение, parent и очистку. Реальный потребитель — road/sidewalk/curb модуля world; земля, здания, фонари и авторская вставка пока используют обычные меши.

Пакетный путь пока не поддерживает faceUV: такой запрос явно отклоняется, чтобы не потерять раскладку при замене на единичный куб пакета. Атласные корпуса домов остаются на обычном пути отрисовки с общим UV-source.
