# Локальные пешеходы (`npc`)

Клиентский модуль «Игра», опционален, вне стартового набора. Зависимости characters/world/simulation. Headless authority — headless.ts, без Babylon/DOM/таймеров; фиксированные 60 Hz, последовательные ticks, стабильные ID npc/<index>, JSON-снимок {tick,actors,arrivals}. Входных пользовательских команд NPC нет: намерения создаёт только authority и валидирует существующий контроллер characters. Реальной сети и сервера нет.

Два ограниченных сухих маршрута Clark/Daley принадлежат контенту npc. Планирование — консервативная сетка 1 м с расширенными AABB статических препятствий (+0.6 м), BFS каждой пары waypoint при создании; внутри прямых удалены промежуточные клетки. Данные скопированы в подготовленные пути. Не считать это навигацией по всему городу: concave outline может блокироваться шире, а тип поверхности/вода пока ограничены выбранными зонами и их тестами. Каждый шаг выполняет characters authority с реальными треугольниками рельефа, polygon-коллизиями и подъёмом до 0.3 м. Индекс characters общий для всей популяции. Нет случайности, решения зависят от tick/ID, короткие остановки разнесены по ID. Долгое отсутствие продвижения даёт паузу; полноценного динамического перепланирования пока нет.

Лимиты: 1–32 человека, 1–8 зон, 2–32 waypoint/зону, до 20000 клеток/зону, целочисленные bounds/точки внутри мира; заблокированные/недостижимые/повторные waypoint отклоняются; число акторов также ограничено количеством уникальных стартовых точек каждой зоны. Нет телепортов, пересоздания маршрутов/моделей в render loop. Между NPC и игроком/другими людьми коллизий и avoidance нет: возможны проходы друг через друга; это явное ограничение, не crowd simulation.

Отображение только JSON-снимков через characters.createView; общий внешний CC0 GLB, материалы/текстуры и простые shadow proxies, отдельные скелеты. Все системы, observers и представления сразу связаны со scope. setup создаёт 8 пешеходов; остановка удаляет их, не основной avatar/cache characters. Сценарий создаёт независимую authority на отдельном scope, не меняет правила основной популяции/игрока. Порядок систем: основной characters, npc, затем системы временного сценария по регистрации.

Проверки: Node — обход стены, валидация/budget/unreachable, разные FPS и длинный перерыв с задолженностью, JSON-ID, реальные городские маршруты и постоянные коллизии. GPU — модели/ходьба/повороты/остановки, 8/24 NPC плюс герой, реальное движение/видимость и повторная очистка. Запуск последовательно с MemoryMax=2G/MemorySwapMax=0/timeout; фиксировать настоящий renderer. 24 NPC — проверка нагрузки, не рекомендуемая плотность: аппаратно 50–55 FPS против обычных 66–77 при 8. visibleMin считает попавшие в active meshes тестовые модели, а не доказанную видимость каждого пикселя сквозь застройку. Скелеты имеют собственные bone textures; это не копии цветовых атласов. Порядок cleanup observer/scopes сохраняется; API snapshot после остановки отклоняется.
