# Персонаж (`characters`)

Клиентский модуль «Игра», вне стартового набора. Требует simulation/world/geometry. Публичные клиентские определения и типы — index.ts. Headless entry point — headless.ts, без Babylon/DOM/core/таймеров. Один локальный персонаж local-player принадлежит owner local; это ID, назначенные authority прототипа, не сетевая идентификация.

## Authority и протокол

createCharacterAuthority принимает неизменяемое описание коллизий world и начальный tick. Статические AABB и площадки копируются в индекс X/Z с ячейкой 32; ограничения размеров/числа ячеек проверяются. step принимает строго следующий целочисленный tick; его вызывает фиксированный clock simulation в порядке регистрации. Скорость 1.8 м/с, бег 7, нормализация диагонали на authority. Объём 0.7×1.8, консервативная прямоугольная проекция, подшаги <=0.1 м и скольжение по X/Z. Подъём <=0.3 м, спуск/уклон следуют статической плоскости и площадкам. Прыжок: вертикальная скорость 5.5 м/с, гравитация 16 м/с², grounded/verticalSpeed/airborneTicks/landedTick в снимке; удар головой о нижнюю грань AABB, приземление на верхнюю, сход с высокого края начинает падение. Намерение jump одноразовое, в воздухе новый импульс запрещён. Нет динамической физики, плавания и полёта. shortcut: статический мир с одной общей плоскостью и прямоугольниками; пересмотреть перед лестницами произвольной формы, транспортом. Коллизии не зависят от LOD, мешей и загруженности секции.

MoveCommand — JSON `{type:'move',characterId,sequence,tick,x,z,run,jump}`. Tick — номер последнего полученного серверного снимка, не клиентское время: authority запрещает будущее и возраст >30 тиков. Проверяются точная структура, конечность/диапазоны, owner, ID, безопасная последовательность (>последней; пропуски разрешены для восстановления после потерь), максимум один принятый пакет за tick. Старые/повторные команды не применяются. Интенсивность задаётся x/z в [-1,1], позицию клиент не присылает. Через 12 тиков без свежей команды движение останавливается. Receipt `{accepted,reason}`. Snapshot — замороженная копия плоских JSON-полей tick/id/ownerId/x/y/z/yaw/moving/running/lastSequence.

createLocalConnection даёт send(command):Promise<Receipt>, snapshot() — последний неизменяемый снимок, step(tick), close(). Это локальный адаптер; createCharacterAuthority/step не входят в клиентский API экземпляра. Доставка всегда через очередь до следующего тика, без скрытого синхронного изменения состояния при send. Наблюдаемые задержка/джиттер/потери конфигурируются в тиках, seed LCG32 явный; очередь <=64, поздний пакет валидируется по tick/sequence authority. Закрытие разрешает ожидающие Promise с closed и освобождает очередь. Реальной сети, reconnect и предсказания нет. При переносе на сервер headless authority и clock запускаются в Node, клиент сохраняет send/кеш снимка; регистрация локальной системы остаётся только у локального адаптера.

## Отображение и жизненный цикл

API клиента: send и snapshot, без изменяемой позиции; getAssetStatus/subscribeAssetStatus — состояние загрузки; createView(ownerScope) — локальный renderer снимков для основного и тестового персонажа. Рендерер не меняет authority. Источник AssetContainer приватен и не передаётся через публичный API.

Вместо кубической заглушки используется новый CC0-человек из внешних официальных пакетов Quaternius. Файлы из chicago-test не копируются. Полное происхождение, лицензии, проверенный список клипов и воспроизведение — public/models/human/SOURCES.md, manifest.json, scripts/extract-character-sources.py и scripts/prepare-character.mjs + retarget-character.mjs. 5970 треугольников, один skinned mesh/материал, 65 костей, атласы 1024²/512², GLB около 0.85 MB. Геометрия/текстуры/материал источника разделяются экземплярами; скелет и состояние проигрывания отдельные. Модель нормализуется до 1.8 м. В runtime семь клипов: Idle/Walk/Jog/Sprint/Jump_Start/Jump_Loop/Jump_Land; выбираются по состоянию прыжка/движения/бега снимка; наблюдаемая скорость меняет темп клипа, без дублирования правил симуляции. Штатный AnimationGroup делает скелетное проигрывание; веса клипов экспоненциально переходят к целевому (95% за 150 мс), включая прерывание перехода; группы с весом <0.005 останавливаются; начальная idle-поза применяется до показа. Геометрия, материалы, кости и keyframes не пересоздаются каждый кадр.

createCharacterAssets — управляемый сервис с одним локальным fetch и AbortController, штатным LoadAssetContainerAsync, ready Promise и наблюдаемыми loading/ready/error. Синхронный setup запускает этот принадлежащий scope сервис, не бесконтрольную async-задачу. Ошибка видна в панели «Детали» и metadata представления; временный loading capsule не является финальной моделью. Network fetch отменяется на остановке, поздний контейнер немедленно dispose, завершение после disposal не добавляет модель в сцену. Source AssetContainer кешируется один раз на модуль; createView создаёт native экземпляр из него, отдельный lifetime владеет placeholder. Root, instances/skeletons/groups, observer, source container, fetch и панель сразу связаны со scope. При остановке рендера source cache остаётся у владельца characters, при остановке модуля освобождается целиком.

Импортированные Mesh регистрируются через geometry.registerMeshes(scope), поэтому shadows использует реальную skinned-геометрию, включая мелкие части. PBR-материал и skeleton инвалидируют статический кеш теней штатным путём. Renderer и камера обновляются в начале onBeforeRender до LOD/теней, чтобы позиции и камеры совпадали с текущим снимком. characters сам не меняет ввод и источник расстояний.

## Проверки

tests/characters.test.ts: одинаковый результат 30/60/144 FPS и после длинного перерыва с сохранённой задолженностью; стены/скольжение/бордюры/уклон/слишком высокая ступень; диагональ/TTL; структура/NaN/owner/частота/sequence/устаревание; задержка/джиттер/потери/перестановка, остановка/восстановление и закрытие очереди; данные коллизий реального мира. Снимки в assert сравнивать как плоские значения, не Babylon-граф.

Сценарий ▶ 6 s: 16 отдельных локальных authority с теми же правилами и world.collision, команды движения/бега и разнесённых по времени прыжков. Все модели разделяют asset cache, сохраняют отдельные скелеты/группы; плюс основной герой, всего 17 моделей. Origin тестовых authority — сетка 4×4 на стартовой дороге, камера следует за центром толпы, radius 13. Основной персонаж не получает тестовых команд. При cleanup удаляются observers/модели/скелеты/системы/очереди; diagnostics actors/visibleMin/tick/distance/lastSequence. Между людьми столкновения пока не реализованы: сценарий проверяет статические коллизии, рендер и анимации, не NPC AI. Тяжёлые браузерные проверки запускать последовательно с MemoryMax=2G/MemorySwapMax=0/timeout.

Дополнительные tests/character-asset.test.ts проверяют бюджет GLB, SHA, один primitive/материал/skin, 65 joints, наличие семи клипов, корректные конечные quaternion/translation tracks и отсутствие root motion. Браузер проверяет реальное изменение кости бедра при Sprint, проход/стену/UI, сокращение и восстановление камеры, отдельный scenario, и три повторных запуска без накопления скелетов/материалов.

Offline-подготовка удаляет треки, которые во всех runtime-клипах совпадают с bind pose (476 из 910). Если хотя бы один клип меняет данную кость/свойство, треки сохраняются во всех клипах для правильного возврата и смешивания. Тест бюджета ограничивает число каналов клипа <=80; пересмотреть при расширении библиотеки.

Обычное движение всегда выбирает Walk_Loop (authority 1.8 м/с), Shift — Sprint_Loop (7 м/с); Jog сохранён в файле, автоматически по порогу скорости не выбирается. Темп Walk ограничен 1.2×. Направление модели экспоненциально догоняет yaw снимка по кратчайшей дуге (95% за 180 мс), первый снимок применяется сразу. Сглаживание только визуальное: положение, направление движения, коллизии и JSON-снимки остаются authority. Дополнительных групп/мешей/скелетов разворот не создаёт. Тесты проверяют выбор клипа, скорости, границу ±π и независимость поворота от FPS.

Для нового центра CollisionWorld дополнительно содержит постоянные абсолютные XYZ-треугольники поверхностей и outline у AABB зданий. Ground берётся barycentric по треугольникам из 32 м индекса; вода не является полом, крыши не телепортируют героя наверх. Broad phase сохраняется, точный polygon/radius тест не блокирует пустые углы AABB; support/landing используют тот же контур. Один локальный scalar height выбирает верхнюю доступную поверхность, полноценные многоуровневые проходы ещё не заявлены. createCharacterAuthorityFactory(world) валидирует/копирует индексы один раз и возвращает фабрику независимых authority(startTick,spawn?): тест 16 людей делит статические данные, но не их состояние. wrapper createCharacterAuthority остаётся совместим. Общий лимит grid entries 1M и triangles 200k проверяется до роста циклов; outlines <=256. Не копировать весь город шестнадцать раз и не связывать коллизии со стримингом.
