# Modular Game

Локальная основа игры без выбранного сеттинга: Babylon.js, TypeScript, Vite, React UI на Radix Themes с иконками Lucide. Без сервера и БД.

## Запуск

Node.js 24.12+:

```sh
npm ci
npm run dev
```

Открыть http://localhost:5175. Мышь вращает камеру, колесо меняет масштаб.

```sh
npm run check
npm test
npm run build
npm run preview
```

## Что уже есть

- Сцена на весь экран, FPS и кнопка «Модули» со всплывающими настройками; применение набора пересоздаёт сцену. Игровой режим пока отсутствует, позже он станет отдельным модулем.
- Неприменённые изменения отмечены точкой на кнопке «Модули»; пояснения зависимостей доступны при наведении. Успешное сохранение не создаёт уведомлений, ошибки остаются видимыми.
- Чекбоксы модулей, автоматическое включение зависимостей, запрет отключения используемой зависимости, сохранение набора в localStorage и сброс.
- Кнопка «Детали» у запущенного модуля с инфо-панелью: перемещаемое окно с закрытием. Панель симуляции показывает секунды, тики и задолженность.
- Типизированные зависимости, проверка графа, обратная очистка и обработка неудачного setup.
- Два примера: площадка и зависимый от неё маяк. Его визуальная анимация следует снимку часов симуляции.
- Опциональный модуль симуляции (включён по умолчанию): headless local authority с фиксированными 60 Hz. Задолженность после зависания сохраняется, за кадр обрабатывается не более 240 тиков. Низкий FPS не меняет скорость часов после догоняния.

## Добавить модуль

Создать `src/modules/<id>/index.ts` или `index.tsx`, объявить через `defineModule` из `src/core/context.ts`, указать `requires`, зарегистрировать в `src/registry.ts`. Публичный API возвращается из `setup`, чужой API доступен через `deps`. Все ресурсы регистрируются через `scope.onDispose` сразу после создания. См. площадку и маяк.

Core предоставляет `onFrame` (монотонная разница времени в миллисекундах, до рендера) и `panels`. Для своей инфо-панели передать React-элемент из `setup` и сразу зарегистрировать очистку: `scope.onDispose(core.panels.register('module-id', 'Название', <Info />))`. Core хранит регистрации панелей; React отображает кнопку «Детали», окно и содержимое внутри общей темы Radix, размонтирует панель при очистке. Оболочка UI — `src/main.tsx`, окно — `src/core/panel-window.tsx`. Оформление берётся из компонентов библиотеки, CSS отвечает только за размещение. Состояние и подписки содержимого принадлежат React-компоненту; подписки очищать в `useEffect`. Пример — `src/modules/simulation/index.tsx`. Окна закрываются при пересоздании сцены. Перемещение — за заголовок мышью/касанием или стрелками с фокусом на заголовке, закрытие — кнопкой или Escape.

Время доступно через объявленную зависимость `simulationModule` и `deps.simulation.snapshot()`. Маяк требует симуляцию, поэтому отключать её нужно вместе с маяком. Применение набора создаёт новые часы с нуля.

`npm run check` проверяет типы (включая отрицательные тесты) и границы импортов. Это защита от случайных нарушений, а не sandbox для недоверенного кода. Модули — доверенный исходный код проекта.

## Будущий мультиплеер

Сейчас реализованы часы authority, не игровая симуляция и не сетевой протокол. Первая механика должна добавить сериализуемые команды, валидацию на authority и снимки состояния. Будущий сервер владеет игровым состоянием и набором игровых модулей; локальные чекбоксы не смогут менять правила общей сессии. Клиент рисует снимки и отправляет намерения.

`src/simulation` не зависит от браузера и Babylon. Транспорт, сетевой имитатор, prediction/reconciliation и сервер пока отсутствуют. Непрерывная фоновая симуляция браузером не гарантируется. Полные правила развития — в [AGENTS.md](AGENTS.md).
